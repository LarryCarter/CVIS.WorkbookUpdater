# Team Intake Message

Team,

For the CVIS modernization / PtB recovery plan, we need to complete a rapid application rationalization so we can prepare an executive-ready plan with dates, owners, dependencies, risks, and recovery actions.

For each CVIS / legacy application, tool, script, DLL, service, console app, or support component assigned to you, please provide:

1. Application / tool name
2. Business function: what it does
3. Primary users or consuming team
4. Classification: customer-facing, user-facing, internal support, vault support, DLL/plugin, service, console app, script, or database
5. Usage frequency, if known
6. Approximate lines of code, if known
7. Complexity: Low / Medium / High
8. Migration disposition: keep, refactor, fold into CVIS/Unity, deprecate, defer, or BAU support
9. Whether it is required for Phase 1 / day-one operational continuity
10. Known blockers, dependencies, or testing concerns
11. Recommended execution owner
12. Current RYG status: Red / Yellow / Green
13. If Yellow or Red: reason, action plan, owner, date it became at risk, and expected recovery date

The purpose is to separate customer-facing capabilities that must move first from internal support utilities that may be handled as BAU, later-phase migration, or deprecation. We need enough detail to support milestone planning, PtB readiness, and executive-level date confidence.

Please return updates in the shared workbook Data Intake tab or as CSV/YAML using the provided template.
